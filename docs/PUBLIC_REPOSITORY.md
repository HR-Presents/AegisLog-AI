# Public repository guide

AegisLog is maintained as a public defensive-security project. This page explains where visitors should go for the most common project interactions.

## Use AegisLog

Start with the main `README.md`, then use:

- `docs/INSTALL.md` for installation and Windows executable guidance.
- `docs/QUICKSTART.md` for a first investigation.
- `docs/USER_GUIDE.md` for the complete workflow.
- `docs/COMMANDS.md` for CLI reference.
- `docs/TROUBLESHOOTING.md` for common problems.

## Report a problem

Use the GitHub bug-report template for reproducible, non-sensitive problems. Sanitize logs and screenshots before posting.

For security-sensitive vulnerabilities, use the private process described in `SECURITY.md` instead of a public issue.

## Suggest an improvement

Use the feature-request template for defensive, local-first improvements. AegisLog intentionally avoids offensive automation, destructive remediation, credential theft, persistence, evasion, and unauthorized access workflows.

## Contribute

Read `CONTRIBUTING.md` before opening a pull request. Focused changes with tests and clear validation are preferred.

## Share feedback

The public User Review issue form is the supported way to share an honest rating, recommendation, strengths, and improvement ideas. Reviews and testimonials are never fabricated; README attribution requires explicit permission from the reviewer.

## Privacy

Do not post credentials, API keys, tokens, production logs, customer information, personal data, private hostnames, or other sensitive telemetry in public project spaces.

AegisLog itself is local-first and does not add usage telemetry simply to identify who runs the application.
