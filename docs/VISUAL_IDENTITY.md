# AegisLog Visual Identity

AegisLog uses a restrained security-operations visual system designed for long terminal sessions and evidence-heavy investigation.

## Brand hierarchy

1. **Startup / repository hero / report cover:** full shield-signal mark and AEGISLOG wordmark.
2. **Workspace headers:** compact AegisLog signature plus a dominant workspace title.
3. **Investigation content:** brand is expressed through typography, spacing, and the blue identity accent rather than repeated large logos.

The logo is intentionally not repeated as decoration inside every card or table.

## Rules

- Aegis blue is the only decorative/identity color.
- Green, amber, and red must communicate actual state or severity.
- Important names and actions use bright neutral text, not rainbow colors.
- Screen titles must visually dominate subtitles and metadata.
- Avoid nested decorative borders and repeated banners.
- Avoid neon gradients, hacker clichés, skulls, robots, generic padlocks, and excessive circuit motifs.
- The product mark combines an angular protective shield with a telemetry pulse to communicate protection + observable evidence.

## Terminal

The terminal uses a text-safe approximation of the mark on startup and a compact `◆ AEGISLOG` signature on inner workspaces. The full startup lockup is intentionally larger than navigation text.

## GitHub

The README begins with the full SVG identity. Capability names are bold and visually separated from descriptions. Screenshots added to the repository should use the same palette and should not contain unrelated desktop chrome or sensitive telemetry.

## Reports

HTML reports should use the same midnight/blue identity for their masthead and neutral evidence surfaces for content. Severity colors remain semantic. Reports must remain self-contained and printable.
