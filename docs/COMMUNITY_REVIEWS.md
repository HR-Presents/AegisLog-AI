# AegisLog Community Reviews

Public reviews help future users understand how AegisLog performs in real environments while giving maintainers concrete feedback to improve the project.

## Leave a review

Use the GitHub **User review** form:

https://github.com/HR-Presents/AegisLog-AI/issues/new?template=user_review.yml

The form asks for:

- an overall 1–10 rating;
- whether you would recommend AegisLog;
- the AegisLog version/build you used;
- operating system and installation type;
- workflows you tested;
- what worked well;
- what should improve;
- an optional short public quote that may be featured in the README only when you explicitly grant permission.

## Featured reviews

No community testimonials are featured yet.

We will only add a quote here or to the README when all of the following are true:

1. the review was submitted publicly through the repository;
2. the reviewer supplied the quote themselves;
3. the reviewer explicitly allowed README/testimonial use;
4. attribution uses the reviewer's public GitHub username;
5. the quote is not materially rewritten to change its meaning.

Negative and mixed reviews are welcome. Reviews are for honest product feedback, not only promotion.

## Privacy

AegisLog does not phone home merely to count or identify users. Running the application locally does not automatically create a public GitHub record.

GitHub interactions such as stars, forks, issues, reviews, pull requests, and commits are public signals only when a user chooses to perform those actions.

Before posting a review, remove credentials, tokens, production logs, personal data, private hostnames, customer information, and other sensitive material.

## What public GitHub activity means

- **Star** — a user publicly chose to support/bookmark the repository; it does not prove installation or usage.
- **Fork** — a public copy of the repository for experimentation or development.
- **Review issue** — direct public feedback from a person who says they used AegisLog.
- **Pull request / commit** — a public contribution to the codebase.

These distinctions keep adoption signals transparent without adding invasive application telemetry.
