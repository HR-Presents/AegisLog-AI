# AegisLog AI V0.2 Intelligence Layer

V0.2 expands the local-first CLI with structured parsing, live monitoring, anomaly scoring, and question-driven investigation.

## Commands

```bash
aegislog analyze examples/auth.log
aegislog threats examples/auth.log
aegislog anomalies examples/access.log
aegislog ask "What looks suspicious?" examples/auth.log
aegislog watch /var/log/auth.log
aegislog scan /var/log
aegislog report examples/auth.log --output report.json
aegislog config --provider none
aegislog doctor
```

## AI design

`ask` currently uses a deterministic local investigation summary. The provider abstraction deliberately separates log collection from model access. Before a future remote provider receives context, AegisLog builds a minimized prompt and redacts common passwords, tokens, secrets, and API keys.

The intended provider contract is defensive: distinguish observations from hypotheses, avoid unsupported compromise claims, and recommend investigation/remediation rather than offensive action.

## Live watch

`watch` tails an existing file from its current end and evaluates each newly appended event. This makes it suitable for a live demonstration with application, SSH, or web logs without requiring a daemon.

## Parsers

V0.2 recognizes generic text, syslog-like records, JSON/journald records, and common web access-log records. Parser output is normalized into a small Event model so later Docker, Apache, Nginx, auditd, and application-specific adapters can share the same detection pipeline.

## Anomalies

The anomaly module is intentionally lightweight and local. It scores rare event classes by frequency. It is not presented as proof of malicious behavior; anomaly output is an investigation lead.
